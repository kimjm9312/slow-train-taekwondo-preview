# 개발자 인수인계

## 기존 시제품과 달라진 점

기존 HTML 시제품의 `localStorage`와 소스 내 고정 데이터는 운영 데이터로 사용하지 않습니다. 현재 첫 화면은 `app/page.tsx`에서 실제 React 앱을 렌더링하고, 모든 운영 데이터는 `/api/v1/*`를 통해 D1 데이터베이스에서 읽고 씁니다. 기존 `public/prototype`은 사진 등 원본 자산 보관용이며 앱 실행을 담당하지 않습니다.

## 서버 구조

- 인증: PBKDF2-SHA256 비밀번호 해시, 256비트 임의 세션, 서버 DB에는 세션 토큰 해시만 저장
- 권한: `requireUser`, `requireAdmin`, `ownsChild`를 API마다 적용
- 데이터: 23개 관계형 테이블, 외래키와 중복 방지 인덱스
- 예약: 한 SQL 문장 안에서 마지막 정원을 재확인하여 참가/대기 처리
- 미디어: R2 객체 저장소, JPG·PNG·WEBP와 8MB 제한
- 기록: 모든 생성·수정·삭제·승인·반려를 `audit_logs`에 기록

## 동시 예약 보장

`server/booking.ts`의 `reserve()`는 화면에 보인 숫자를 신뢰하지 않습니다. 서버가 `INSERT ... SELECT ... WHERE confirmed_count < capacity`로 다시 확인합니다. 동시에 요청해도 한 명만 참가로 들어가며 다음 요청은 대기, 참가와 대기가 모두 차면 409 `SESSION_FULL`을 반환합니다.

## 배포 데이터

`.openai/hosting.json`의 `DB`와 `MEDIA` 바인딩을 사용합니다. `drizzle/0000_spicy_nuke.sql`은 23개 테이블과 인덱스를 생성합니다. 첫 인증 요청에서 `server/bootstrap.ts`가 테스트 계정, 센터 콘텐츠, 6개 시간대 수업을 한 번만 초기화합니다.

## 운영 전 점검

1. 테스트 계정 비밀번호 변경 또는 제거
2. 실제 SMS 발송 어댑터 연결 후 `developmentCode` 반환 제거
3. 푸시 발송 작업(APNs/FCM/Expo Push) 연결
4. 개인정보 처리방침·이용약관 확정
5. 실제 센터 회원 데이터 이관
6. 관리자 2단계 인증 도입 검토

## 자동 검증 결과

`tests/api.integration.mjs`가 실제 로컬 D1을 상대로 다음을 확인합니다.

- 부모·관리자 인증 및 자녀 소유권
- 예약과 취소
- 정원 1명 수업에 두 요청을 동시에 보냈을 때 참가 1명·대기 1명
- 세 번째 신청자의 만석 거절
- 참가 취소 시 대기자 자동 승급
- 공지사항 생성·수정·삭제
- 모든 변경의 감사 기록
